# 安装到现有 Paper 26.2 大服

这是一个独立小游戏插件，和 DeathRun 一样使用插件管理的专用世界。继续使用你现在的 Paper 26.2 / Java 25 服务器，不需要新开服务器，也不需要 Multiverse、WorldEdit 或额外资源包。

## 放置两个文件

正常关闭现有服务器后：

1. 把单独提供的 `CubeCraftTowerDefence-<版本>.jar`（本次单独下载的 JAR） 放进服务器的 `plugins/`。如果以前安装过塔防插件，移走旧的塔防 JAR，只保留一个版本。其他插件保持原样。
2. 解压配套数据 ZIP，把里面的 `plugins/` 文件夹合并进服务器根目录。最终应有 `plugins/CubeCraftTowerDefence/maps/ImprovedFarm.schem`，不要多套一层文件夹。

ZIP 没有 `server.properties`、启动脚本、`eula.txt`、主世界或 `config.yml`，不会要求替换大服的这些文件。已有塔防的 `recovery/`、玩家进度、背包布局和证据文件必须保留。塔模型全部内置在 JAR 中，无须另装模型插件或资源包。

如果以前自行放过 `plugins/CubeCraftTowerDefence/tower-models/catalog.yml`，它仍优先于内置模型。要使用这次完整的 82 阶段模型，停服时把这个旧的 `tower-models/` 文件夹移到服务器之外备份；不要保留只覆盖部分塔的旧目录。

## 首次创建 Farm

正常开服后，在控制台执行（游戏内 OP 执行时加 `/`）：

```text
ctdinstall create 1
```

`1` 表示 1v1，两名玩家就能开局；可选 1–6，例如 `ctdinstall create 6` 为 6v6，需 12 人。不写数字默认 6v6。

该命令先核验地图 SHA 和模型，再创建全新的 `ctd_farm` 虚空世界；已有同名世界会拒绝创建。它会备份并更新塔防自己的配置，启用完整 Farm 场景及明确标注的工程运行参数，不修改其他小游戏配置。Paper 26.2 会把该独立世界存放在 `服务器主世界目录/dimensions/minecraft/ctd_farm/`；插件按专用维度加载它，不替换主世界地形。

然后**正常重启这台现有服务器一次**，不要使用 `/reload`、PlugMan 或热卸载。重启后插件自动加载 `ctd_farm`，分批导入场景，日志会显示进度，通常需要数分钟；这段时间塔防开局被阻止，其他小游戏继续运行。

```text
ctdinstall status
```

等日志出现 `Managed Farm READY`，或状态为 `phase=READY` 后，执行：

```text
ctdpreflight
```

必须确认没有 blocking 项，再让玩家加入。以后正常开服时自动加载这个世界，不会重新粘贴或覆盖已完成地图。

## 游玩

v124 起，插件验证所有权的专用 Farm 世界会保护场景和塔体，拦截原生拆放方块、容器/附魔台交互、液体、活塞、爆炸与自然方块变化。塔防菜单、建塔、升级和出售照常使用；主世界和其他小游戏不受该保护影响。管理员的地图导入/验证重置使用直接 API，仍可正常执行。

如果其他插件把参赛者传出比赛世界，塔防会按正常离场处理，恢复其赛前物品、状态和位置。由塔防自身执行的开局与结束传送不触发误离场。

玩家在你现有大厅输入：

```text
/ctdjoin
/ctdvote
```

达到配置人数后会开始 3→2→1，传送进入比赛。排队期间仍在现有大厅，Settings 和背包布局使用队列偏好，不清空大厅背包。比赛保存玩家状态，离开用 `/ctdleave`，结束/退出时恢复原位置和原状态。请继续保留恢复日志；断线恢复仍需实际服务器验收。

管理员可在游戏内用 `/ctdinstall visit` 前往 Farm 的观景平台（`ctd_farm`，约 `62.5 104 -15.5`）；这是管理员查看地图的传送，不是加入比赛。返回请使用大服现有的回城/大厅指令。不要把服务器主出生点改到这里。

## 安装异常

- `CREATED`：世界已创建但配置尚未完成。核对报错后，用 `ctdinstall configure 1` 完成配置，再正常重启。
- `BUILD_FAILED`：查看日志中的冲突/错误，排除磁盘空间、写入权限或所有权问题后，使用 `ctdresetfarm 28d24136afe8` 执行验证修复。失败场景不会被误认为空场景重试；初次导入仍只接受全 AIR 的目的区域。
- 导入中正常关服会取消并回滚本次初始粘贴，下次开服继续；导入中崩溃则保留 `BUILDING`，并由已有的不干净重启门禁阻止开局。管理员核对日志后使用 `ctdresetfarm 28d24136afe8` 走带回滚的验证重置，完成后才转为 READY。不会自动覆盖未知残留。
- 若 `farm-reuse-gate.yml` 损坏，插件保留文件并阻止开局；核对日志后使用同一个验证重置指令修复，不能删除记录来跳过检查。
- 所有 TD 队列、比赛和地图操作必须空闲，才能创建或修改部署配置。
- 若所有权标记、UUID 或维度元数据 不符/丢失，插件拒绝重建或接管世界；恢复对应备份后再正常重启。不要删除 `managed-farm.yml` 或世界目录来跳过检查。

## 地图和模型是什么

v123 将 11 类塔的 82 个阶段升级为现代细节版：保留木制哨塔、火炮、冰核、石英雷塔与绿色 Leach 的辨识轮廓，加入打蜡铜、凝灰岩、深板岩、紫水晶和新式光源。高等级和两个分支有不同的顶饰、炮口、护甲或晶体。它是主动美术改编，不能视为原版逐方块还原。塔位尺寸、攻击与升级数值不变，不需要资源包。

从 v122 更新时，只需停服替换 JAR，保留已有地图和恢复数据。没有外置模型目录时会自动使用内置新模型；有外置 `tower-models/` 时须先移出备份。已经 READY 的地图不要重新创建或重置。

完整 Farm 场景是按官方历史画面重建的近似版本，保留已有社区调整路线，包含谷仓、筒仓、苹果树、动物雕塑、农田和周边场景。11 类塔的全部 82 个运行时等级/分支键有内置方块模型。它们不代表原版世界文件，也不是逐方块原图提取。

`optional-schematics/Farm-Reconstructed.schem` 是额外提供的完整场景 schematic，供自行编辑或导出时使用，**本安装流程不需要手动粘贴它**；插件会组合已校验路线和内置场景，避免偏移或重复粘贴。没有需要在主世界刷出的实体模型。

CI 证据包括编译、全部领域用例（数量见随包 build-manifest）、两次真实 Paper 启动和独立世界创建/重启加载检查；多人游玩与服务器上的其他插件兼容性仍需在你的大服实际确认。

普通开服只做不会改动地图的启动检查；方块放置、容器回滚等破坏性回归测试仅在 CI 专用测试维度中运行。


如果大服有清理实体插件，请让它保留带有 `cubecrafttd_tracked` scoreboard tag 的塔防实体。比赛期间怪物所在区块由塔防插件持有加载票据；外部插件强行删除比赛实体仍会触发保护性停赛和地图完整性检查。


塔防专用世界会关闭随机方块刻，防止泥土长草、草方块消退等自然变化破坏重建场景。该设置只作用于核验过所有权的塔防世界，不冻结共享时间，也不修改主世界或其他小游戏世界的规则；旧地图已经产生的变化不会被自动覆盖。
